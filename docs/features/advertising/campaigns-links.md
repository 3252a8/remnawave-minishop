# Кампании, ссылки и UTM

Создайте кампанию с понятным названием и уникальным старым start-кодом.
Допустимы 2–64 латинские буквы, цифры, `_` и `-`. Служебные пространства
`ref_`, `p_`, `promo_`, `plan_`, `gift_`, `admin_`, `ticket_`, `webapp_auth_`
зарезервированы для своих сценариев.

В карточке откройте **Ссылки**, задайте название объявления, посадочный путь и UTM.
`utm_source` обязателен. Backend выдаёт короткий код `ad_…`, связанный с кампанией.
Канонические UTM ссылки и фактически полученные параметры контакта хранятся отдельно.
Одинаковый UTM-набор не превращается в новую кампанию автоматически.

| Адрес | Пример |
| --- | --- |
| Бот | `https://t.me/example_bot?start=ad_example` |
| Main Mini App | `https://t.me/example_bot?startapp=ad_example` |
| Именованный Mini App | `https://t.me/example_bot/my_app?startapp=ad_example` |
| Веб | `https://shop.example/shop/?campaign=ad_example&utm_source=telegram` |

Для именованного приложения укажите короткое имя, настроенное в BotFather.
Если Telegram отключён или имя бота ещё неизвестно, используются веб-ссылки.
Веб-адрес строится из `PUBLIC_APP_URL` с поддержкой префикса пути, исходного query и fragment.
Посадочный путь должен быть локальным: внешний адрес или `//host` отклоняется.

**Пауза** прекращает новые рекламные контакты. **Архив** сохраняет накопленную историю.
Старые опубликованные коды остаются алиасами; существующий служебный конфликт требует
новой ссылки и ручной проверки, а не переименования опубликованного адреса.
Рекламодатель назначается по внутреннему ID существующего аккаунта. Команда `/my_ads`
показывает только назначенные этому аккаунту кампании.
