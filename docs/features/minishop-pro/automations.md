# Создание и запуск автоматизации

В **Маркетинг → Автоматизации** цепочка объединяет условие входа, аудиторию и шаги доставки. Например, можно напомнить о незавершённой оплате, прекратить напоминания после покупки и сравнить результат с группой, которой ничего не отправили.

## Выбрать условие входа

1. Откройте **Готовые шаблоны** или создайте автоматизацию с нуля. Шаблоны для брошенной оплаты, пробного периода, продления и возвращения клиентов создаются выключенными. Дайте цепочке название, по которому оператор узнает её в истории клиента.
2. Выберите режим и фактор. **Событийная** цепочка реагирует на новое событие, например просмотр тарифов или ошибку автопродления. Переход в горячие лиды срабатывает при **изменении** группы. Режим **По расписанию** проверяет подходящих клиентов каждые четыре часа. Он подходит, например, для сегмента «Подписка кончается через 3 дня».
3. При необходимости добавьте [фильтры рекламы](./audiences.md). Настройте [шаги и каналы](./delivery.md), затем отправьте тест себе. Для напоминаний о продлении сверьтесь с уже включёнными [уведомлениями Minishop](../notifications.md), чтобы клиент не получил два похожих сообщения.

## Решить, кто войдёт первым

| Настройка | Что произойдёт |
| --- | --- |
| Только будущие совпадения | Текущие участники сегмента фиксируются как исходная группа. Они смогут войти после выхода из сегмента и нового совпадения. |
| Текущие + будущие | Текущую подходящую аудиторию можно запустить сразу, а новые совпадения будут попадать в цепочку дальше. |
| Один раз на клиента | Повторного входа после участия не будет. |
| После выхода и нового входа | Для повторного участия требуется новое совпадение после выхода из аудитории. |
| После cooldown | Повторное участие допускается после заданной паузы. Этот интервал относится ко входу в цепочку. Задержки между сообщениями задаются в шагах. |

Для запуска текущей аудитории откройте предварительный просмотр. Сопоставьте **Подходят сейчас**, **Будут запущены** и причины исключений. Например, часть клиентов уже проходит эту цепочку. При большом объёме укажите интервал распределения запуска в минутах и подтвердите рассчитанную группу. Повторное подтверждение того же запуска не дублирует участие.

## Измерить эффект

До запуска укажите процент **Контрольной группы**, если хотите оценить, сколько покупок добавила рассылка. Эти клиенты учитываются в сравнении и пропускают сообщения эксперимента. Например, при контроле 10% примерно десятая часть подходящей аудитории останется без сообщения. Настройка действует на распределение участников, уже доставленные сообщения сохраняют историю.

Следите за доставкой и покупками на карточке цепочки. Конверсия по сообщениям и конверсия по охваченным клиентам имеют разные знаменатели. Для сравнения короткой и длинной цепочки используйте показатель по клиентам. В [бизнес-аналитике](./analytics.md) посмотрите, как изменилась доля оплат относительно контроля.

## Изменить или перенести цепочку

Экспортируйте одну автоматизацию из меню карточки или несколько из общего списка. При импорте JSON для совпадающих названий доступны **Заменить**, **Переименовать**, **Пропустить**. Импортированные цепочки создаются выключенными. Проверьте тексты, часовой пояс, каналы, скидки и соответствие рекламных условий новому магазину перед запуском.

Для старых шаблонов откройте **Проверить поведение цепочки**. Предпросмотр показывает по шагам, где предлагается остановка или пауза. Применение именно этой рекомендации сохраняет тексты, расписания, действующих участников и историю. Обычное сохранение изменений аудитории или шагов выключает цепочку. Проверьте статус участников и предварительный расчёт перед новым запуском.
