# Персональные предложения и атрибуция продаж

Персональное предложение создаётся в шаге автоматизации для одного получателя. По нему можно связать оплату с конкретным сообщением. Для общих кодов, которые администратор распространяет вручную, используйте [справочник промокодов Minishop](../promocodes.md).

## Добавить скидку в сообщение

1. В редакторе шага задайте процент персональной скидки. При нулевой скидке код не выдаётся и кнопка персонального предложения не появится у клиента.
2. Оставьте код бессрочным или укажите срок в днях. В тексте можно использовать `{promo_code}`, `{offer_valid_until}` и `{offer_valid_days}`. Например, «Ваша скидка действует до {offer_valid_until}». Подстановка покажет срок именно выданного предложения.
3. Добавьте кнопку применения предложения или перехода к тарифам и проверьте её тестовой доставкой. Для нескольких языков проверьте переводы подписи и текста шага.
4. При доставке получатель получает собственный одноразовый код. Пересылка сообщения другому человеку не передаёт право на скидку. Если клиент вернулся в магазин сам, доступный код может появиться в предложениях при оплате. Код, уже занятый ожидающим платежом, пропускается при подборе предложения.

## Найти ранее выданный код

В разделе **Автоматизации** откройте блок **Персональные промокоды**. В активном списке видны действующие предложения. Использованные, просроченные, тестовые или недоставленные коды можно найти в архиве. У записи сохраняются значение кода, связь с получателем и шагом, срок и состояние. Так оператор может отличить истёкшую скидку от кода, который получил другой клиент.

## Как оплата относится к сообщению

Сначала Minishop ищет доставленное сообщение с персональным кодом, применённым при оплате. Если точного совпадения нет, используется **окно атрибуции**. Покупка относится к последнему подходящему доставленному сообщению этому клиенту в пределах окна. Одна покупка даёт одно начисление в статистике цепочек. Неуспешная доставка в расчёте не участвует.

Например, клиент получил напоминание в понедельник в 10:00, вернулся сам и оплатил во вторник в 09:00. При окне 72 часа покупка может попасть в результат напоминания даже без кода. При окне 0 учитываются только точные совпадения по персональному коду. Начальное окно — 72 часа. Изменить его можно в настройках безопасности автоматизаций.

На карточке цепочки сравните отправки, покупателей и отнесённую к сообщениям выручку. Такая выручка отвечает на вопрос «после какого сообщения произошла покупка». Дополнительные продажи относительно естественного спроса оценивают через [контрольную группу](./automations.md). [Рекламный источник](./audiences.md) может учесть тот же заказ в своём отчёте.
