# Подключение AI и база знаний

В **Плагины → PRO → Настройки → AI-поддержка** администратор выбирает модель, знания и режим работы. Новая установка начинает в режиме **Отключено — без генерации**. Подготовить подключение и сохранить знания можно заранее. Для работы с обращениями нужна активная лицензия Minishop PRO. Доступ к модели и её оплату вы оформляете у выбранного провайдера.

## Выбрать подключение

| Способ | Что потребуется |
| --- | --- |
| Совместимый API | Собственный API-ключ, точный HTTPS-адрес API и модель с поддерживаемым протоколом. Провайдер определяет тариф и квоту. |
| Свой аккаунт ChatGPT | Аккаунт с доступом к выбранной модели и разрешённым входом по коду устройства. Расход запросов учитывается в пределах квоты аккаунта. |

**Через API.** Добавьте именованное подключение. Укажите Base URL, протокол Chat Completions или Responses и формат ответа, который поддерживает модель (JSON Schema, JSON Object или текст). Сохраните ключ. Обновите каталог моделей или введите точный ID, при необходимости задайте уровень рассуждений и таймаут. Нажмите **Проверить модель** и дождитесь результата. Тестовый запрос может расходовать квоту. При изменении адреса предыдущий ключ и проверку нужно настроить заново.

**Через ChatGPT.** Создайте подключение соответствующего типа и нажмите **Войти**. Откройте выданную страницу OpenAI и введите одноразовый код там. После входа Minishop обновит список моделей и выполнит проверку. Если код истёк, запустите вход заново. Смена модели или перезапуск обработчика требует новой проверки текущей сессии, она запускается автоматически. В случае ошибки проверьте вход, доступ к модели и остаток квоты. Запросы продолжаются через выбранное подключение после успешной проверки.

Выберите проверенное подключение для агента. Можно хранить несколько подключений. При удалении активного подключения агент выключается. **Выйти** очищает сохранённый вход текущей установки. Для полного переноса установки с подключениями используйте [резервную копию](../backups.md). Если настроен внешний ключ шифрования, для восстановления потребуется тот же ключ.

## Подготовить базу знаний

В **База знаний Markdown** редактируется единый документ. В новой установке есть стартовый текст. Замените примеры сведениями своего магазина: какие приложения поддерживаются, как проверить оплату, что спросить при проблеме с подключением и когда передать обращение оператору. Модель получает документ целиком вместе с доступной перепиской.

Сохранение публикует новую версию для следующих ответов. Предел документа — **256 КиБ в UTF-8**. Дополнительно действует лимит контекста подключения. Если редактировали вдвоём, при конфликте ваши правки останутся в редакторе. Сохраните нужные фрагменты перед загрузкой актуальной версии. Пустой сохранённый текст очищает документ.

## Настроить и проверить режим

1. Выберите язык ответа, разрешённые категории, расписание и тихие часы. Пустой список категорий не разрешает автономные ответы. Одинаковые часы начала и конца отключают тихий период.
2. Установите суточный предел ответов, число автоответов подряд, число уточнений, лимит контекста и время генерации. Укажите срок хранения черновиков и аудита от 1 до 90 дней.
3. Начните с режима **Ответы с подтверждением администратора**. Проверьте в тестовых обращениях обычный вопрос, отсутствие ответа в базе и просьбу позвать человека. Оператор должен получить возможность проверить и изменить ответ перед доставкой.
4. Для **Автономного диалога** подтвердите проверку пилота и включите нужные категории. Это явное решение администратора. Работа с новыми сообщениями начинается согласно правилам, старую очередь включение не рассылает.

Для проверки работы на конкретном обращении откройте [Совет AI, черновики и передачу оператору](./ai-tickets.md).
